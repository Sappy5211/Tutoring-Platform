## The product (operator's words, normalised)

An India-built online learning platform, launching with **Mathematics**, then Science (Physics, Chemistry, Biology). Five pillars:

1. **Notes & teaching docs** — a Notion/RemNote-style block editor holding structured course notes. Operator supplies source material; the system helps author/structure it. Notes must **export to PDF**.
2. **Interactive testing** — practice questions and assessments per topic, with adaptive difficulty and progress tracking.
3. **AI answer checking** — a student may write a correct answer in a different form (`0.5` vs `1/2`, `2(x+3)` vs `2x+6`, different variable order, worded proof). The grader must accept mathematically equivalent answers, not string-match.
4. **AI tutor** — a chat assistant students ask questions of, grounded in the platform's own notes (RAG). Model: **DeepSeek API** (decided by operator; not wired up yet).
5. **Live teacher booking** — students book a 30-minute Zoom call with a real teacher. Scheduling, availability, payment, join links.

Plus, from RemNote/Notion inspiration: **flashcards with spaced repetition**, **formula handling (LaTeX/KaTeX)**, **AI-assisted note generation from supplied material**, and a **knowledge/brain graph** view of how topics interconnect.

"Reinforcement learning and all jazzy techniques" = the operator wants a genuinely **adaptive** engine (what to show next, when to review, difficulty targeting). Treat this as a requirement for an adaptive-mastery system, and be honest in your lane about which algorithms are actually appropriate versus buzzword.

## Hard constraints

- **India-first.** Indian students, Indian curricula (CBSE / ICSE / state boards / JEE / NEET), Indian pricing psychology, Indian payment rails, Indian data-protection law (DPDP Act 2023), Indian mobile-network and low-end-Android reality.
- **Build order:** UI/frontend first, then backend. Operator supplies the teaching material.
- **The build will be executed later by a cheaper coding agent.** Therefore every recommendation must be concrete enough to implement without further research: name libraries and versions, name files, give schemas, give exact acceptance criteria. Vague advice is a failed deliverable.
- **Existing house stack** (from prior projects, prefer unless you have a strong reason): React 18 + TypeScript + Vite + Tailwind v4 + React Router + Zustand, `lucide-react` icons, `@xyflow/react` for node canvases, `react-force-graph-2d` for graph views, `recharts` for charts, `motion` (Framer Motion successor) for animation.
- **Reference, not gospel:** the operator's previous chat UI (CarbonAnswer, at `~/CarbonAnswer/frontend`) is explicitly described as *outdated*. Mine it for structure and lessons; the new UI must be materially better, not a copy.
